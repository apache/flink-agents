Events carry data between Actions. Each Event has:

| Field | Purpose |
| --- | --- |
| `type` | Identifies the Event type used to match Actions. |
| `attributes` | Holds the Event's payload as named values. |
| `id` | Identifies the Event. A new ID is generated by default when the Event is created and cannot be changed afterward. |

One Event can trigger multiple Actions. For matching by type or payload, see
[Trigger Conditions]({{< ref "docs/development/create-agent/actions#trigger-conditions" >}}).

## Input and Output Events {#special-events}

`InputEvent` and `OutputEvent` connect an Agent to the surrounding Flink pipeline:

| Event | Role | Payload |
| --- | --- | --- |
| `InputEvent` | The framework creates one for each input record. Matching Actions start processing that record. | `input` contains the record. |
| `OutputEvent` | An Action sends one to emit a result downstream. It bypasses Action matching. | `output` contains the result. |

Use `InputEvent.from_event(event).input` in Python or
`InputEvent.fromEvent(event).getInput()` in Java to read an input record.

## Creating and Handling Events {#unified-event}

Create an `Event` with a custom type and attributes to pass data to another Action.
A subclass is optional. The following snippets use the `review_ready` Event from
[Sending Events]({{< ref "docs/development/create-agent/actions#sending-events" >}}).
They run inside Action methods; framework imports and job setup are omitted.

{{< tabs "Creating and Handling Events" >}}
{{< tab "Python" >}}
Send the cleaned review from the first Action:

```python
review = InputEvent.from_event(event).input
ctx.send_event(Event(type="review_ready", attributes={"text": review.strip()}))
```

In an Action registered with `@action("review_ready")`, read the payload:

```python
text = event.get_attr("text")
ctx.send_event(OutputEvent(output=text))
```
{{< /tab >}}
{{< tab "Java" >}}
Send the cleaned review from the first Action:

```java
String review = (String) InputEvent.fromEvent(event).getInput();
ctx.sendEvent(new Event("review_ready", Map.of("text", review.trim())));
```

In an Action registered with `@Action("review_ready")`, read the payload:

```java
String text = (String) event.getAttr("text");
ctx.sendEvent(new OutputEvent(text));
```
{{< /tab >}}
{{< /tabs >}}

## Custom Event Subclasses

Define a subclass when you want to reuse an Event type with named accessors and payload
validation. Keep its payload in `attributes`. The `ReviewReadyEvent` below represents
the same `review_ready` type and `text` payload used above.

When the framework deserializes an Event at a JSON boundary, custom types arrive as
generic `Event` objects. Provide `from_event` / `fromEvent` to validate the payload and
obtain your typed representation.
Use `reconstruct_from` / `reconstructFrom` to preserve the original Event's ID and
attachments.

{{< tabs "Custom Event" >}}
{{< tab "Python" >}}
```python
from typing import ClassVar

from flink_agents.api.events.event import Event


class ReviewReadyEvent(Event):
    EVENT_TYPE: ClassVar[str] = "review_ready"

    def __init__(self, text: str) -> None:
        if not isinstance(text, str):
            raise ValueError("ReviewReadyEvent requires a string 'text' attribute")
        super().__init__(type=self.EVENT_TYPE, attributes={"text": text})

    @classmethod
    def from_event(cls, event: Event) -> "ReviewReadyEvent":
        if event.type != cls.EVENT_TYPE:
            raise ValueError("Expected a review_ready Event")
        result = cls(text=event.get_attr("text"))
        return result.reconstruct_from(event)

    @property
    def text(self) -> str:
        return self.get_attr("text")
```
{{< /tab >}}
{{< tab "Java" >}}
```java
import com.fasterxml.jackson.annotation.JsonCreator;
import com.fasterxml.jackson.annotation.JsonIgnore;
import com.fasterxml.jackson.annotation.JsonProperty;
import org.apache.flink.agents.api.Event;

import java.util.Collections;
import java.util.Map;
import java.util.UUID;

public class ReviewReadyEvent extends Event {
    public static final String EVENT_TYPE = "review_ready";

    public ReviewReadyEvent(String text) {
        this(null, Collections.singletonMap("text", text));
    }

    @JsonCreator
    public ReviewReadyEvent(
            @JsonProperty("id") UUID id,
            @JsonProperty("attributes") Map<String, Object> attributes) {
        super(id, EVENT_TYPE, attributes);
        if (!(getAttr("text") instanceof String)) {
            throw new IllegalArgumentException(
                    "ReviewReadyEvent requires a string 'text' attribute");
        }
    }

    public static ReviewReadyEvent fromEvent(Event event) {
        if (!EVENT_TYPE.equals(event.getType())) {
            throw new IllegalArgumentException("Expected a review_ready Event");
        }
        return reconstructFrom(event, ReviewReadyEvent::new);
    }

    @JsonIgnore
    public String getText() {
        return (String) getAttr("text");
    }
}
```
{{< /tab >}}
{{< /tabs >}}

Constructing a `ReviewReadyEvent` from text creates a new Event. `from_event` / `fromEvent`
produces a typed representation of an existing Event, retaining its ID instead of creating
a new Event occurrence. Both examples reject a missing or non-string `text` attribute.

For Java, `@JsonCreator` and `@JsonProperty` let Jackson restore the subclass during
recovery. The constructor accepts the saved ID and attributes, and is also used by
`reconstructFrom`. `@JsonIgnore` on `getText()` keeps the payload in `attributes` without
serializing a second top-level `text` property. If your payload contains custom objects,
restore their types in this constructor too.

Use the subclass when sending an Event, and its factory when handling one. These
snippets run inside the sending and receiving Actions respectively:

{{< tabs "Using a Custom Event" >}}
{{< tab "Python" >}}
```python
# In the sending Action:
ctx.send_event(ReviewReadyEvent(text="A useful review."))
```

```python
# In an Action registered with @action(ReviewReadyEvent.EVENT_TYPE):
review = ReviewReadyEvent.from_event(event)
ctx.send_event(OutputEvent(output=review.text))
```
{{< /tab >}}
{{< tab "Java" >}}
```java
// In the sending Action:
ctx.sendEvent(new ReviewReadyEvent("A useful review."));
```

```java
// In an Action registered with @Action(ReviewReadyEvent.EVENT_TYPE):
ReviewReadyEvent review = ReviewReadyEvent.fromEvent(event);
ctx.sendEvent(new OutputEvent(review.getText()));
```
{{< /tab >}}

## Serialization and Typed Values {#json-serialization}

Event attributes must support JSON serialization. For supported values and conversions,
see [Data passed between Java and Python]({{< ref "docs/development/create-agent/choose-apis-and-languages#data-passed-between-java-and-python" >}}).

### Event Transfer and Replay

Whether you need to restore payload types depends on how the Event reaches an Action:

- **Between Java Actions:** normal execution passes Java objects directly, preserving
  their types. No payload reconstruction is needed.
- **To or from Python Actions:** Events pass through JSON serialization. Flink runs on
  a Java runtime, so this also applies between two Python Actions.
- **Replay from an ActionStateStore:** persisted Events are restored from JSON.
  Application-defined payload objects may become `Map` values even in a Java-only Agent.

### Restoring Typed Values

At the Python–Java boundary, restoring an Event's type and restoring objects inside
its payload are separate steps:

| Data at a JSON boundary | What the receiving Action gets |
| --- | --- |
| Built-in Event, such as `InputEvent` or `ChatRequestEvent` | The corresponding built-in Event class. Framework-declared field types are also restored; for example, `ChatRequestEvent.messages` contains `ChatMessage` objects. |
| Custom Event, such as `ReviewReadyEvent` | A generic `Event`. Call your subclass's `from_event` / `fromEvent` for typed access. |
| Application-defined object in the payload, such as a review model in `InputEvent.input` or `ChatResponseEvent.structured_output` | JSON data, typically a `dict` / `Map`. Reconstruct the application type if needed. |

Restoring a built-in Event does not restore application-defined types inside it. For
example, a restored `ChatResponseEvent` can still carry structured output as a `dict`
or `Map` rather than your application class.

For example, if your application defines a `ReviewData` type, convert an input payload
inside the receiving Action as follows. `ReviewData` is a Pydantic model in Python or
a Jackson-deserializable class in Java:

{{< tabs "Restore an Input Payload" >}}
{{< tab "Python" >}}
```python
review = ReviewData.model_validate(InputEvent.from_event(event).input)
```
{{< /tab >}}
{{< tab "Java" >}}
```java
ReviewData review = new ObjectMapper().convertValue(
        InputEvent.fromEvent(event).getInput(), ReviewData.class);
```

`ObjectMapper` is imported from `com.fasterxml.jackson.databind`.

## Built-in Events and Actions

Flink Agents provides built-in Actions for common operations such as calling chat
models, executing tools, and retrieving context. These Actions are registered with
your Agent by default, so you do not need to implement or register them yourself.

Register the Resources required by the operation, then send the corresponding request
Event from your Action. The built-in Action handles the request and sends a response
Event that your Actions can handle to continue the workflow:

| Task | Events | Guide |
| --- | --- | --- |
| Call a chat model | `ChatRequestEvent`, `ChatResponseEvent` | [Chat with Models]({{< ref "docs/development/calling-llms/chat#chat-events" >}}) |
| Call tools | `ToolRequestEvent`, `ToolResponseEvent` | [Tool Use]({{< ref "docs/development/calling-llms/tool_use#built-in-events-and-actions" >}}) |
| Retrieve context | `ContextRetrievalRequestEvent`, `ContextRetrievalResponseEvent` | [Vector Stores]({{< ref "docs/development/vector-search/vector_stores#built-in-events-and-actions" >}}) |
| Call a decision model | `DecisionRequestEvent`, `DecisionResponseEvent` | [Decision Models]({{< ref "docs/development/decision_models#event-driven-calls" >}}) |
