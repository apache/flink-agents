## Orphan-state 内存泄漏修复（issue：Kafka/Fluss 持久化 ActionState 恢复后残留外来 key）

实现路径 2a：恢复时按 key-group 归属过滤外来 key，使其永不进入 `actionStates` 缓存。

改动文件：
- `ActionStateStore`：新增默认方法 `setOwnershipFilter(Predicate<String>)`（null=不过滤，向后兼容，内存/测试后端安全）。
- `KafkaActionStateStore` / `FlussActionStateStore`：加 `ownershipFilter` 字段 + `shouldRetain(stateKey)`，rebuild/replay 时跳过非本 subtask 负责的 key；Fluss 覆写 `setOwnershipFilter`。
- `DurableExecutionManager.handleRecovery`：签名改为 `(OperatorStateBackend, @Nullable Predicate<String> ownershipFilter)`，rebuild 前 `setOwnershipFilter`。
- `ActionExecutionOperator.initializeState`：把 `stateManager = new OperatorStateManager()` 上移到 `handleRecovery` 之前，算 `maxParallelism` + `KeyGroupRange`，用
  `stateManager.isKeyOwnedByCurrentSubtask` 构造 predicate 传入。复用了 `tryResumeProcessActionTasks` 已有的 key-group 归属判定。

测试：
- `KafkaActionStateStoreTest`：新增 `testRebuildStateFiltersForeignKeys` / `KeepsAllKeysWhenNoFilter` / `KeepsUnparseableKey`（fail-safe）。
- `FlussActionStateStoreIT`：新增 `testRebuildStateFiltersForeignKeys`（真实集群复现 A 保留、B 丢弃）。
- `DurableExecutionManagerTest`：`handleRecovery(opBackend, null)` 调用同步更新。

验证状态：
- `mvn -o -pl runtime spotless:check` 通过（已 spotless:apply 格式化）。
- runtime 模块未能离线编译：plan 模块依赖 `dev.cel:cel:jar:0.12.0` 未在 ~/.m2 缓存，且离线无法下载 → 无法跑 runtime 单测。属环境限制，非代码问题。api 模块 124 文件编译通过。

注意：归属判定必须用 Flink key-group 语义（`isKeyOwnedByCurrentSubtask`），不可用 Kafka partition 分配（两套不同哈希）。
